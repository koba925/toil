Toil のソースコードは以下のコーディングスタイルに従います。

## 全般

Python の初心者でプログラミング言語処理系を初めて作る人にもわかりやすいコードを心がけてください。

# 詳細ルール

基本的には PEP-8 に従います。ただし、以下は例外とします。

* 行の長さは 88 文字までとします。ただしテストコードではこだわりません。
* ひとまとまりの意味を持つ複数の文を 1 行で書くことがあります。画面にできるだけ多くの情報を入れ、見通しをよくするためです。
* トップレベルの定義の間は基本的に２行空けますが、ごく短い定義はまとまり具合によって 1 行のみ、または行を空けずに続けて書くことがあります。
* 継承関係を無視して厳密に型を判定したいときは type()を使います。
* import したシンボルの有効範囲を狭めるため、import を先頭に置かないことがあります。
* 書籍で説明する予定であることと、コードを短く見通しよくしたいことからコードにはコメントを入れません。
  * コメントを入れなくても読みやすいコードになるよう心がけてください。
  * ただし、変数名や関数名は長すぎないようにします。
* 引用符はダブルクォーテーションを使います。
  * toil のソースコードは ` r""" """ ` で囲んで記述します（toil のソースコードに引用符を使うようになることを見越して）。
* 式を表す変数には_expr、値を表す変数には_val をつけます。そのため、arg の値のリストを表す変数名は arg_vals ではなく、args_val となります。ただ値または式であることがわかればよい場合は単に val または expr と書き、この場合は複数なら vals、exprs となります。

## エラーチェック

* エラーチェックは最小限とします。Python のエラーで止まっても何が起きたかわかれば問題ないものとします。
* エラーは assert で上げます。エラーメッセージは f"{メッセージ} @ {関数}() : {エラーとなった値}"とします。" : {エラーとなった値}" については表示しても意味がない場合などに省略することは可能です。
* エラーチェックをつける代表的なケースは以下の通りです。
  * match で適切な case がなかった場合。
  * 再帰の基底ケースとしてのチェック。
  * 型をチェックしないと警告が出る場合。

## 実行例

* toil.py のメインセクションの `# Example` コメント以下に実行例を置きます。これは Toil のコードの例示と、実装した機能のテストを兼ねます。
* エラーになる実行例はコメントアウトして書きます。
* できるだけ `eval()`、`walk()` または `run()` などを使って end-to-end で動作例を示したり、実行結果を確認できるようにします。
* `eval()`、`walk()` または `run()` などでは十分に動作を例示・説明しづらい場合は `scan()`、`ast()`、`compile()` などで途中結果を示すことも検討します。
* 0 や 1 は False・True やその他の特別な値と混乱する場合があるため、実行例やテストで使う数は 2 から始めます。
* `<` などが正しく動作することについては Python を信用することにして網羅的にはテストしません。正しく Python の機能が呼び出せていることが確認できればよいものとします。
* Toil が自分でエラーチェックをしている個所以外のエラー（引数の数、0 除算など）はテストしなくても構いません。

## テスト

* テストメソッドは処理系のソースコードに現れる位置と対応付けやすいように並べます。
 （書籍では基本的に実行例を見せて説明する方針なので、テストは動作確認のしやすさに重点を置きます）
* テストのコードは実行例に準じます。
* テストにするのは `eval()`、`walk()` または `run()` の実行例のみとし、`scan()` や `ast()`、`compile()` などの実行例が存在してもテストに入れません。これはテストが内部構造に依存しないようにするためです。ただし、`walk()` または `run()` だけではテストが不十分と考えられる場合は追加を検討します。
* コメントになっているエラーの行があればそれらもテスト化します。


## フォーマットとスペースに関する注意
* 括弧（丸括弧 `()`、角括弧 `[]`、波括弧 `{}`）のすぐ内側には余分なスペースを空けない（PEP-8 準拠）。
  * 良い例: `{Ident("-"): Ident("neg")}`
  * 悪い例: `{ Ident("-"): Ident("neg") }`
