Toil を題材として書籍「[育てて学ぶ はじめての自作プログラミング言語](https://zenn.dev/kb84tkhr/books/learning-by-growing-language)」を執筆中です。まだドラフトですが、第 1 部を公開し、第 2 部を執筆中です。

## 書籍のコンセプトとターゲット

- 厳密さよりも読者が楽しく読み進められることを優先する。楽しく読んでいるうちに自然とプログラミング言語処理系の作り方が身についているようにする。
- 読者は「Python の基礎（リスト、辞書、クラス）は知っているが、言語処理系は初めて」という想定。概念はわかりやすく説明する。説明のギャップや難易度が急に上がったりすることがないようにする。
- 少しずつ機能を追加してすぐ動くようにし、達成感を感じられるようにする。一度に多すぎる概念を導入しない。

## 書籍用ソースコード

このプロジェクトの `book` ディレクトリには書籍の節ごとのコードを作成しています。
その中に完全なソースコードを置いており、ディレクトリ内で処理系やテストが実行できます。

ディレクトリ名は `mmnn_xxx` という形をしており、`mm` は章番号、`nn` は節番号、`xxx` は節の内容を表す文字列です。
ディレクトリ名を `<DIR>` とすると、主要なファイルは以下の通りです。

* `<DIR>/toil.py`：Toil 言語処理系
* `<DIR>/test_eval.py`：評価器のテスト
* `<DIR>/test_twi.py`：ツリーウォーク式インタプリタのテスト
* `<DIR>/test_ici.py`：中間コード式インタプリタのテスト
* `<DIR>/diff.txt`：ひとつ前の節の toil.py との差分

具体的には以下のような配置になります。

```
book/
  0101_constants/   --- 定数を実装する節
    toil.py
    test_eval.py
  0102_pseudo_func/ --- 疑似関数を実装する節
    toil.py
    test_eval.py
  ...
```

プロジェクトルートにある `toil_final.py` やその他のファイルは書籍用の処理系の試作品のコードです。おおむね同じように書いていきますが、書籍の流れ上いったん異なる書き方をしたり、よりよい書き方を見つけて書き直したりしている部分があります。テスト項目の漏れの確認などには利用できます。

* draft.md には書籍に書こうと思っているネタを忘れないようにメモしています。タイポ・誤りがあったり、付け加えるとよい興味深いトピックがあったら随時指摘してください。体裁については指摘不要です。

## 書籍用ソースコードのテスト

`book` 内の書籍用のソースコードをテストする際には `.venv/bin/pytest` を使ってください。

## 読者向けサンプルコード

読者向けのサンプルコードを https://github.com/koba925/toil-book に公開しています。
このリポジトリは、`book` ディレクトリ内にある節ごとのディレクトリをもとに作成しています。
ディレクトリ名をタグにして、任意の節のコードを参照できるようにしています。

* `book/build_repo.sh` でローカルにサンプルコードを収めたリポジトリを作成します。
* `book/check_repo.sh` でローカルのリポジトリのタグを一覧表示して目視確認できるようにします。
* `book/push_repo.sh` でローカルのリポジトリを GitHub に強制 push します。

## 書籍の原稿

書籍の原稿は別プロジェクトで管理されています。必要に応じて参照してください。

`~/projects/zenn-content` ディレクトリを `<ZENN>` とします。

* `<ZENN>` はエンジニア向け情報共有サイト [zenn](https://zenn.dev/) 用の原稿執筆用プロジェクトです。
* `<ZENN>/books` は zenn 書籍の原稿を置くディレクトリです。ここには複数の書籍の原稿があります。
* `<ZENN>/books/learning-by-growing-language` にはこのプロジェクトの公開済みの原稿があります。
* `<ZENN>/books/learning-by-growing-language-draft` にはこのプロジェクトの公開予定のドラフト原稿があります。


## 開発の進め方とパート（部）ごとの方針
* **第2部（第4章〜第6章）**: ツリーウォーク式インタプリタ（TWI）の機能拡張に専念します。この期間中、中間コード式インタプリタ（ICI）に関するコードやテスト（など）は修正しません。AI は ICI 側の追従やテスト追加を指摘・提案しないでください。
* **第5部**: 第 2 部で行った機能拡張を中間コード式インタプリタ（ICI）に反映させます。
